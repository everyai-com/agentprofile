Open-Source + Service Launch Plan · Aug 2026

Profile Cloud Launch Plan

How to ship the agent profile cloud as an open-source project and a hosted service: license, open-core boundary, trust roadmap, pricing, and an 8-week launch sequence. Companion to the architecture report.

Strategy in one paragraph: Apache-2.0 everything user-facing, with client-side zero-knowledge encryption fully open — trust is the product. Self-hosting is a one-click "Deploy to Cloudflare" button into the user's own free-tier account, which is your top-of-funnel; the paid cloud sells convenience, teams, and the signed skill registry. Claim the open "profile" naming space (AgentVault and SkillSync are taken), list on all four MCP registries plus Anthropic's Connectors Directory, and launch with Show HN as the main event.

1 · Positioning

Tagline pattern that works in this space (Supermemory: "your memories in every LLM, one command"):

"Your agent's identity, everywhere. One profile — skills, credentials, memory — synced to every agent tool."

  • Differentiator vs memory-only rivals (Supermemory, OpenMemory): the bundle. Skills + encrypted credentials + memory = a portable agent identity, not a memory add-on.
  • Differentiator vs secret managers (Infisical, Doppler): agent-native grants and one endpoint that also carries skills and memory.
  • Differentiator vs Executor (UsefulSoftwareCo/executor, MIT, 3.5k★ — the closest competitor): Executor is an integration gateway — what your agents can call (MCP/OpenAPI tools + credentials + policies). We are the agent identity — what your agents know and are: portable SKILL.md skills with format translation, cross-tool memory, and zero-knowledge (not merely centralized) credentials. Position as complementary ("run your tools through Executor, carry your profile with us") and consider an Executor adapter rather than a head-on fight over the credential/policy overlap.
  • Differentiator vs everyone: open source + self-host on your own Cloudflare account for free; zero-knowledge server.
  • Naming: "vault", "memory", and "skills" namespaces are crowded (Infisical agent-vault; SkillSync is YC W26 and adjacent). The profile framing is open — pick a name there and register domain, GitHub org, and npm scope on day one.

2 · License & open-core boundary

License: Apache-2.0 across server, SDKs, CLI, and crypto. Every direct comparable in agent memory (Mem0, Zep, Letta, LiveKit, Supabase-style) chose permissive; AGPL/fair-code friction kills integrations in an ecosystem where agent-tool vendors must embed your client. The 2024–25 relicensing disasters (Redis→Valkey, HashiCorp→OpenTofu) argue for picking the durable license on day one; FSL is the fallback only if cloud strip-mining ever becomes real. Use DCO, not CLA — the asymmetric CLA is what made those relicensings possible and contributors know it.

Open (Apache-2.0)

  • MCP server + REST API
  • All client-side E2E encryption — the trust core
  • CLI + SDKs, skill format & translators
  • Single-user self-host: Deploy-to-Cloudflare button (DO + D1 + R2, free-tier-friendly)
  • Basic OAuth (GitHub/Google)

Paid cloud / EE

  • Managed hosting, backups, multi-device sync at scale
  • Team/org profiles & sharing, RBAC
  • SSO/SAML/SCIM, audit log export
  • Hosted skill registry with signing + injection scanning
  • Support, compliance reports

Pricing anchor (consistent with Mem0 $19–249, Letta $20, Infisical $9/user): Free → ~$12/mo individual → ~$29/user/mo team → enterprise. Self-hosters convert when they want teams or no-ops; expect monetization mostly from users who never self-host.

3 · Trust roadmap

For a product storing credentials, security is the marketing. The Bitwarden/Vaultwarden pattern: crypto is client-side, fully open, independently audited — the server is zero-knowledge, so even your paid cloud never sees plaintext. That converts the biggest objection into the pitch.

  • Day one: zero-knowledge architecture doc, security.txt + responsible-disclosure policy, GitHub Security Advisories, npm provenance (--provenance via GitHub Actions OIDC) on every package.
  • Before credential-sync GA: independent crypto audit (Cure53 / Trail of Bits class); publish it in full.
  • Registry launch: Sigstore-signed skills with publisher identity bound to CI OIDC, verified on install; automated prompt-injection scan before activation.
  • First enterprise interest: SOC 2 Type I (Probo or similar to bootstrap), Type II 6–12 months later.

5 · Repo & community bar

  • README: one-line value prop, animated demo GIF above the fold, one-command install, client-compatibility matrix (Claude Code / Cursor / Codex badges), architecture diagram.
  • Docs on Mintlify (the AI-devtool default): per-client quickstarts, copy-paste one-liner, llms.txt.
  • GitHub Discussions (searchable Q&A) + Discord (live energy); 10–15 good-first-issues labeled at launch; CONTRIBUTING.md; fast first-PR reviews.
  • Keep the MCP tool surface small (~5–8 tools) — oversized tool lists exhaust agent context windows and hurt reviews.

6 · 8-week launch sequence

Wk 1–2

Foundations. Name + domain + GitHub org + npm scope. Phase-1 build (MCP server, DO profile, skills + memory). Apache-2.0, DCO, security.txt. README with GIF, Mintlify docs. Start Connectors Directory submission now.

Wk 3

Quiet listing. Publish to Smithery/Glama/mcp.so/PulseMCP; awesome-list PRs; companion skill on the skill directories. Deploy-to-Cloudflare button working end-to-end. Open Discussions, label good-first-issues.

Wk 4

Private beta. 20–50 users from MCP/Claude Code communities. Instrument the key metric: a profile connected to a second client. Fix streaming/auth/timeout edges (avoid buffering through Cloudflare — 100s ceiling).

Wk 5

Seeding. Creator early access + demo kit. Launch blog post: "Why your agent's identity shouldn't live in one tool." Credential sync ships behind a beta flag with the zero-knowledge doc.

Wk 6

Launch. Show HN + X demo thread + public Discord, same day. Founder in comments. GitHub trending via the star spike (topics: mcp, claude-code, ai-agents).

Wk 7

Echo. Product Hunt; TLDR/Bytes/daily.dev pitches; creator videos drop; Cloudflare technical build post.

Wk 8

Retention. Connectors listing live; ship the top HN-requested feature publicly; first community call; changelog + early metrics; SEO comparison pages (vs Supermemory, OpenMemory, SkillSync).

7 · Success metrics & risks

  • Healthy month one for a front-page MCP-era launch: 1–3K stars, steady registry installs, Discord growth. North-star: % of profiles synced to ≥2 clients — that's the product working.
  • Risks: Executor (3.5k★, MIT, active) expanding from tool gateway into memory/portable skills — it has the head start on stars and multi-platform deploys (mitigate: ship the memory + zero-knowledge differentiators first, position as complementary, watch its roadmap); Cloudflare's own Agent Memory beta expanding into this space (mitigate: be the open, cross-cloud-portable option); credential-storage breach headline risk (mitigate: zero-knowledge + audit before GA); skill prompt-injection incident in the registry (mitigate: signing + scanning + quarantine from day one); launching before the demo GIF and one-command install exist (the most common fatal mistake — don't).
