1 · Vision & one-liner

"Your agent's identity, everywhere." One profile — skills, credentials, memory — synced to every agent tool through a single MCP URL. Open source, zero-knowledge, self-hostable on your own Cloudflare account in one click; the hosted cloud sells convenience, teams, and a signed skill registry.

The bet: people now use several agent tools (Claude Code, Cursor, Codex, custom agents), and each one starts from zero — its own skills, its own pasted API keys, its own amnesia. Every piece of the fix exists separately; nobody bundles them. The bundle is the product.

3 · Product & user experience

Core loop

Connect

Each agent tool adds one MCP URL, OAuths once, and becomes a grant — its own identity with its own scopes (skills tags, memory scopes, named credentials; secrets default-deny).

Skills

Add a skill once (upload, registry, or git); every tool receives it in its native format — SKILL.md for Claude Code, rules for Cursor, AGENTS.md/plugin bundles for others — translated at fetch time, versioned, live-pushed.

Memory

Agents call remember/recall; every tool reads and writes the same brain, with provenance ("learned in Claude Code, Aug 31") and per-tool scope filters (work tools never see personal memories).

Secrets

Credentials encrypted on the user's device before upload; delivered just-in-time to granted clients; every read audited; revoke a tool and access dies instantly.

Insanely-easy onboarding (< 60s, no signup)

  • Path A — the agent installs it: landing-page CTA is a copy-paste prompt; the user's own agent creates the profile, writes MCP configs for every detected client, verifies, and teaches a first memory.
  • Path B — one command: npx profilecloud mints an anonymous instant profile (token doubles as claim key), auto-wires detected clients, prints the test: "now ask Cursor what you just told Claude Code." Claim with a login later; secrets unlock only after claiming.
  • Path C — web-first: two-step connect page per client, exact command pre-filled, live checkmark when the first call lands; connection options encoded in the URL (?scopes=dev&approval=browser).
  • Restart-friction killers (offer to restart the client; "waiting for first call…" indicator), pc doctor that prints the fix for every failure, idempotent self-host deploy:setup that prints the one remaining manual step.

MCP surface (≤ 9 tools, byte-budgeted)

get_context() · list_skills() · get_skill(slug, format) · remember(fact, scope)
recall(query, scope) · forget(id) · list_credentials() · get_credential(name) · sync_status()

Description byte-sizes pinned in tests (every byte is paid on every client turn — lesson from Executor). Long-form guidance behind a docs tool, never in always-loaded descriptions. Management (installs, grants, publishing) lives in CLI/dashboard, not MCP.

Memory is a provider interface

MemoryProvider adapters: builtin (DO SQLite + Vectorize, default), Mem0, Supermemory, Zep — users keep the memory service they already use; our grant/audit layer wraps every backend (external providers have no per-client access control — added value either way). Optional mirror mode writes to both so switching providers is lossless. Provider API keys are stored as ordinary E2E-encrypted credentials.

Two deployments, one codebase

Cloud (multi-tenant)

  • Our account; isolation at the DO boundary + per-tenant Vectorize namespaces/R2 prefixes
  • Stripe billing; plan flags in D1, cached in DO

Self-host (single-tenant)

  • Deploy-to-Cloudflare button auto-provisions DO/D1/R2/Vectorize/Queues in the user's account
  • MODE=selfhost: public registry read-only, no Stripe; free tier covers personal use

5 · Security & trust

  • Zero-knowledge secrets: master key derived client-side (Argon2id or keychain; recovery code), never leaves the device. Per-secret DEKs (AES-256-GCM) wrapped by the master key; server stores only ciphertext + wrapped DEK, plus a platform-KEK outer envelope for defense in depth. Team sharing later = X25519 DEK-wrapping per member (Bitwarden org model). This is the wedge vs Executor/Infisical: their operators can read your secrets; we cannot.
  • Grants + audit: per-client scopes and filters enforced in the DO before any data access; every allow/deny logged; approval-gated actions pause and return a browser approval URL (long-poll) — human approval is the default, not model self-approval.
  • Skill supply chain: publish pipeline = validate → Workers AI injection scan → render formats → Sigstore-sign (CI OIDC publisher identity) → live; quarantine flags propagate to installs.
  • Trust roadmap: day one — zero-knowledge architecture doc, security.txt, disclosure policy, npm provenance on all packages; pre-GA of secrets — independent crypto audit (Cure53/Trail of Bits class), published in full; enterprise interest — SOC 2 Type I then II.

6 · Open source & business model

License: Apache-2.0 everywhere user-facing, decided on day one. DCO, not CLA. Every comparable in agent memory chose permissive; AGPL friction kills embedding; the Redis→Valkey and HashiCorp→OpenTofu exoduses prove relicensing after adoption is catastrophic. FSL is the break-glass fallback only.

Open (Apache-2.0)

  • MCP server, REST API, dashboard
  • All client-side E2E crypto — the trust core
  • CLI, SDKs, skill format + translators, memory adapters
  • Self-host via deploy button (free-tier friendly)

Paid cloud / EE

  • Managed hosting, backups, scale sync
  • Team/org profiles, sharing, RBAC
  • SSO/SAML/SCIM, audit export
  • Hosted signed skill registry; support, compliance

Pricing: Free → ~$12/mo individual → ~$29/user/mo team → enterprise. Self-host is top-of-funnel; teams convert for SSO/RBAC/no-ops. COGS ≈ pennies per active user (DO requests dominate) — margin is a non-issue.

9 · Metrics & risks

  • North star: % of profiles synced to ≥2 clients. Supporting: time-to-first-sync, registry installs, weekly active profiles, Discord/Discussions activity. Healthy month one for a front-page MCP launch: 1–3K stars.
  • Risks & mitigations: Executor expands into memory/skills (ship memory + zero-knowledge first; stay complementary) · Cloudflare Agent Memory grows up (be the open, portable, cross-cloud option) · credential-breach headline (zero-knowledge + audit before GA; never log secret fields — lint-enforced) · registry prompt-injection incident (signing + scanning + quarantine from day one) · launching without the demo GIF/one-command install (the classic fatal mistake — blocked in the checklist below).
