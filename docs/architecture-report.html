Agent Profile Cloud

One synced profile — skills, API credentials, and memory — for every agent tool you use. What exists today, and how to build the missing piece on Cloudflare.

Verdict: No single platform does all three today. Memory sync is solved (Mem0/OpenMemory, Supermemory), skills distribution is solved (Skilldex, git-based registries, the Agent Skills spec), and agent-aware secret managers exist (Infisical, Doppler, 1Password) — but nothing composes them into one identity-anchored profile delivered over a single MCP server. That's a genuine gap, and Cloudflare's stack is a near-ideal fit for building it.

Relevant standards worth building on: the Agent Skills spec (SKILL.md, now stewarded by the Agentic AI Foundation, ~40 compatible tools), Agent Plugins 1.0 (portable skills + MCP-config bundles), AGENTS.md, and MCP as the universal transport. Cloudflare itself opened a private beta of "Agent Memory" in April 2026 — a sign this layer is coming to platforms, but still memory-only.

The pragmatic stack right now

If you want ~90% of the outcome today with zero building: Supermemory or OpenMemory for memory (one MCP server, every client), Infisical or Doppler for keys (runtime injection instead of pasting keys into each tool's config), and a private git repo + Skilldex/dotagents for skills. Three logins instead of one, but each piece is mature.

The gap a unified product fills

  • One identity → one profile → one MCP endpoint that serves all three asset types to any client.
  • Cross-format skill translation (SKILL.md ↔ Cursor rules ↔ Codex ↔ AGENTS.md) — today this is manual.
  • Per-client access control spanning all three types ("Cursor gets these 5 skills and the GitHub token, but no health memories").
  • Versioning and team sharing of the whole profile, plus audit of what each agent read.
  • Skill trust: signing/scanning third-party skills for prompt-injection before they enter your profile.

Building it on Cloudflare

The delivery surface is a single remote MCP server on Workers (plus a thin CLI for offline sync). Every agent tool that speaks MCP — Claude Code, Cursor, Codex, custom agents — adds one URL and authenticates once.

Edge / APIWorkers: remote MCP server (Agents SDK McpAgent) + REST API + web dashboard (static assets). Turnstile on signup, WAF + rate limiting in front.
Identity & authWorkers OAuth provider for MCP clients (the Agents SDK ships an OAuth flow); Cloudflare Access in front of the dashboard; per-device tokens with scoped grants per client.
Per-user stateOne Durable Object per user profile: the consistency point for grants, sync cursors, audit log, and live WebSocket push so edits propagate to connected tools instantly.
SkillsR2 for skill bundles (content-addressed, versioned), D1 for metadata/registry/scopes. A translation layer renders SKILL.md into each client's native format at fetch time.
SecretsEnvelope encryption in your own layer: per-user data keys wrap each credential; the master KEK lives in Workers Secrets/Secrets Store. Ciphertext in D1 or DO storage. JIT delivery only to granted clients, every read audited. (Cloudflare Secrets Store itself is for your platform keys — 100 secrets/account, one store — not tenant data.)
MemoryD1 (or DO SQLite) for structured facts with provenance + timestamps; Vectorize for embeddings (Workers AI embedding models) so agents get semantic recall via MCP tools like remember / recall.
Async workQueues + Workflows for embedding pipelines, skill scanning (prompt-injection checks via Workers AI), and format translation. Cron for key-rotation reminders and memory consolidation.

MCP tool surface (v1)

skills:   list_skills, get_skill(format=claude|cursor|agents-md), install_skill
secrets:  list_credentials (metadata only), get_credential  → audited, grant-gated
memory:   remember(fact, scope), recall(query), forget(id)
profile:  whoami, sync_status, list_grants

Security model

  • Grants are per-client, per-asset-type. Each connected tool gets its own token; the DO enforces what it may read. Default-deny for secrets.
  • Zero plaintext at rest for credentials; decryption happens in the Worker only at delivery, never logged.
  • Audit trail in the DO: every secret read and memory query, queryable from the dashboard.
  • Skill quarantine: third-party skills pass an automated injection scan before activation.

Phased roadmap

Phase 1 · 1–2 wk

Personal MVP. One Worker MCP server, DO per profile, D1 + R2, bearer-token auth. Skills + memory only, Claude Code and Cursor as the two test clients.

Phase 2 · 2–3 wk

Secrets + grants. Envelope encryption, per-client grants, audit log, OAuth flow for MCP clients, minimal dashboard.

Phase 3 · 3–4 wk

Seamlessness. Format translation (Cursor rules, AGENTS.md), CLI for offline/dotfile sync, WebSocket live push, semantic memory via Vectorize.

Phase 4

Multi-user. Team sharing, skill registry with signing/scanning, billing. Only if it graduates from personal tool to product.

Cost

For personal/small-team use this fits comfortably in the Workers Paid plan (~$5/mo) — D1, R2, Vectorize, Queues, and DO usage at this scale round to pennies. Verify current limits in the Cloudflare docs before committing to numbers.
